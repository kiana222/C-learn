第 0 步 · 学会使用电脑上的 C 编译器

你截图中的黑色窗口是 w64devkit 终端，不是报错。~ 表示当前在用户目录，$ 是等待输入的提示符；输入命令时不用把 $ 一起打进去。编译器 GCC 负责把 .c 源文件变成能运行的 .exe 程序。

先用下面的双击方式完成第一次练习。熟悉后再用终端手动输入命令，理解“编辑 → 保存 → 编译 → 运行”。

方法一：双击操作，适合第一次使用

  1. 打开本机 E:\C\practice 文件夹，双击 编辑代码.cmd，记事本会打开 hello.c。黑色终端本身不是代码编辑器。
  2. 修改代码后按 Ctrl+S 保存。文件名仍要以 .c 结尾。
  3. 双击 编译运行.cmd。窗口先编译，再运行程序；若有错误，窗口会停住供你阅读。示例应输出 Hello, C! 和 7 + 3 = 10。
  4. 做新题时，复制 hello.c 并重命名为新文件名；把新 .c 文件拖到这两个脚本上，就能编辑或编译它。

方法二：在截图中的 ~ $ 终端手动操作

先在记事本保存 hello.c，再依次输入下面三行命令，每行按一次回车。w64devkit 终端里路径可写成 E:/C/practice：

cd E:/C/practice
gcc -std=c11 -Wall -Wextra hello.c -o hello.exe
./hello.exe

cd 进入练习目录；gcc 编译 C 源文件；-std=c11 选 C11 语言标准；-Wall -Wextra 显示常见警告；-o hello.exe 指定输出程序名；./hello.exe 运行当前目录的程序。第一次也可输入 gcc --version 确认编译器可用。

方法三：用 VS Code 编辑、编译和运行

  1. 双击 E:\C\practice\用VSCode打开练习.cmd，会直接用 VS Code 打开练习文件夹；再点击 hello.c。也可以打开 E:\C\VSCode\Code.exe 后手动选择“文件 → 打开文件夹”。
  2. 编辑后按 Ctrl+S 保存，再按 Ctrl+Shift+B。终端会调用本机的 GCC 编译当前 C 文件，报错会显示在终端中。
  3. 通过编译后，选择“终端 → 运行任务 → 运行当前程序”。这个任务会先编译再运行；需要键盘输入的程序，在终端里输入后按回车。

VS Code 是代码编辑器，实际编译工作仍由 E:\C\w64devkit\bin\gcc.exe 完成。已将 code 和 gcc 加入当前用户 PATH；新开的终端才能直接使用这两个命令。

编译失败时怎么看

  1. 先找第一条含 error: 的信息，看它前面的文件名和行号。缺分号、括号不配对、变量名拼错很常见。
  2. 回到记事本修改、按 Ctrl+S，再重新编译。只修改 hello.c 后直接运行旧 hello.exe，看到的仍是上次编译的版本。
  3. 若提示 gcc: command not found，请从 E:\C\w64devkit\w64devkit.exe 打开终端，或直接用“编译运行.cmd”；若找不到 hello.c，先输入 cd E:/C/practice。
自测：改完源文件后，可以跳过编译直接运行旧 exe 吗？

不可以。hello.c 是源码，hello.exe 是上次编译的结果；每次修改源码都要重新编译，新的内容才会进入 exe。

这里的 GCC 生成 Windows 电脑程序，适合练 C 语法和算法。STM32 固件还需要对应芯片工程和 ARM 交叉编译工具链。以上 E 盘路径仅适用于安装了本地工具的这台电脑；上传到 GitHub 的网页不会附带编译器。

进阶资料：ST 的 CubeMX 代码生成说明、Arm CMSIS 核心寄存器文档、GCC 对 volatile 的说明。这些是补充阅读，网站离线阅读不受影响。
